# Evaluación y herramientas

Ninguna herramienta automática puede confirmar por sí sola que una web sea accesible. Detecta una parte de los fallos y debe combinarse con revisión humana y pruebas con usuarios.

## Revisión recomendada

1. Validar la estructura, nombres accesibles y errores automáticos.
2. Recorrer toda la interfaz solo con teclado.
3. Comprobar foco, ampliación, reflujo, contraste y estados.
4. Revisar textos alternativos, subtítulos y mensajes de error.
5. Probar con lector de pantalla y, cuando sea posible, con personas usuarias.

## Herramientas útiles

- [WAVE](https://wave.webaim.org/) para una primera inspección visual.
- [Axe](https://www.deque.com/axe/) y las herramientas del navegador para reglas automatizadas.
- [WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/) para contraste.
- Validadores del W3C para HTML y CSS.
- Lectores de pantalla como NVDA, VoiceOver o TalkBack.

## Registro de incidencias

Cada incidencia debería incluir ubicación, pasos para reproducirla, comportamiento observado, criterio afectado, impacto para el usuario y propuesta de corrección. La severidad se decide por la barrera real, no por lo fácil que resulte arreglarla.
